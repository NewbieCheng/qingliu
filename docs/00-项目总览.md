# 00 · 项目总览

## 1. 产品定位

清流（Qingliu）是面向业务员、复核员和管理员的**客户资料与银行流水初筛工作台**。它解决的是内部初筛阶段的证据留存和人工核对，不是银行信贷审批系统。

品牌关系：

- 母品牌：今天不加班（企业 AI 应用与智能工作台）
- 产品品牌：青流
- 主张：资料有据 · 测算有序

## 2. 四步流程

1. **上传资料**：PDF / CSV / XLSX；每批最多 10 份、单份 30MB、整批 64MB、PDF 最多 500 页。
2. **确认归属**：确认客户、资料归属和纳入范围；支持人工关联名单。
3. **逐笔核对**：查看解析出的交易、疑点、PDF 原页对照，标记确认/排除/待补。
4. **生成报告**：草稿 → 提交复核 → 复核通过 → 正式内部初筛报告（PDF / Excel / HTML 快照）。

旧资料不会自动纳入新客户；正式报告是快照，后续资料变化不会覆盖已生成报告。

## 3. 角色

| 角色 | 能力 |
| --- | --- |
| `admin` | 账号管理、客户、全部报告、授权 |
| `sales` | 自己创建的客户、上传、核对、草稿、提交复核 |
| `reviewer` | 被授权的客户、复核、签发正式报告 |

身份主路径是工作台 service login；`ql_users` 本地密码是迁移期兜底。账号停用、改密会撤销已有会话。

## 4. 代码地图

```text
frontend/                 React 19 + Vite（原生 CSS，无 UI 框架）
  src/main.jsx            只挂载 React
  src/app/                应用总装、路由表、登录守卫、错误边界
  src/pages/              页面组合：登录、客户、底稿、充值、账户、管理、404
  src/features/           业务域：auth/clients/case/billing/ai-analysis/profile/admin
  src/shared/             公共能力：API、路由、布局、UI、Hook、格式化、样式
  src/shared/styles/      tokens.css + legacy.css，index.css 为唯一入口
  scripts/                架构边界检查、浏览器冒烟
  public/qingliu-*.svg    青流 Logo 包
  dist/                   构建产物（发布时同步）
server/                   Go 单进程
  main.go                 HTTP 路由、启动、配置
  store.go                MySQL Store、查询、事务辅助
  schema.sql              启动建表
  workbench.go            工作台 service login / 计费代理
  worker.go               进程内单执行器（解析、报告任务）
  parser.go               CSV/XLSX/PDF/OCR 解析
  report.go               PDF/Excel/HTML 报告
  ai_analysis.go          AI 文档分析（走工作台网关默认模型）
  domain.go               业务规则/金额/期间/统计
```

前端依赖方向：`app → pages → features → shared`；公共能力不得反向依赖页面或业务域。
目录、边界与新增页面流程见 [`01-前端开发.md`](01-前端开发.md)。

## 5. 运行形态

- 一个 Go 二进制同时提供 API + React 静态文件；没有 Node 常驻进程。
- MySQL 独立库 `qingliu`，不与工作台共用表。
- 后台任务在 Go 进程内单执行器运行；任务写 `ql_jobs`，浏览器关闭不取消，重启可恢复。
- 原始资料和报告以 QLGO1（AES-256-GCM）落在 `DATA_DIR`；数据库只存索引/元数据/加密后的文件路径。
- 计费与支付订单不落清流库，统一代理到工作台后台。

## 7. 重要边界

- 不承诺“识别所有银行/征信版式”；新版式必须逐项核对行数、方向、金额、总额、日期口径。
- OCR 只给原文候选，不自动认定征信余额或贷款资格。
- 不做自动贷款审批、授信结论或对外正式报告；报告仅供内部初筛。
- 不在浏览器保存平台模型 Key、支付签名或服务端凭证。
