# 12 · 查询缓存与操作记录

## 1. 分层

```text
pages              触发查询、展示 loading/error、触发刷新
app/queries        查询键、TTL、失效策略（唯一编排层）
feature/api        业务接口路径与参数
shared/api/cache   内存缓存原语（Map + TTL），不引用业务模块
shared/api/client  网络、CSRF、401、ApiError
```

## 2. 缓存规则

- **权威数据**（余额、权限、报告、交易流水、核对结果）只以服务端为准；内存 `Map` 仅做短 TTL 去重，刷新即清空
- **唯一例外**：原件页 PNG 可进 IndexedDB（`features/case/lib/page-preview-cache.js`），键 `cid:docId:page:sha`，`sha` 变化即 miss。不存资金、权限、报告正文
- 不用 `localStorage` / `sessionStorage` / Service Worker 存业务查询结果
- 键 = 资源 + 规范化参数，如 `clients:<q>:<page>`、`case:<cid>:<range>:<view>:<q>:<page>`
- 手动刷新 / busy 轮询 / 写后传 `force: true` 绕过并覆盖
- 退出登录、401、切换空间清空全部内存缓存
- TTL 只是短期去重，**不是一致性保证**；资金/权限/签发仍以服务端返回为准

| 数据 | 键 | TTL |
| --- | --- | --- |
| 客户列表 | `clients:<q>:<page>` | 10s |
| 底稿详情 | `case:<cid>:<range>:<view>:<q>:<page>` | 8s |
| 管理员成员 | `admin:overview` | 15s |
| 操作记录 | `admin:audit:<params>` | 15s |
| 空间列表 | `profile:spaces` | 15s |
| 个人信息 | `profile:me` | 60s |
| 积分余额 | `billing:balance` | 10s |

失效范围：新建客户 → `clients:*`；底稿写操作 → `case:<cid>:*`；成员增删启停 → `admin:*`；下单/支付 → `billing:balance`；改密/退出/401/切空间 → 全部。写成功后**先失效再查询**。

## 3. 服务端加速与冷数据

- 底稿交易行：服务端按客户 revision 缓存已 evaluate 的行，`bump` 失效；接口仍按筛选分页返回（每页 50）
- 原件页：`ETag` / `X-Document-SHA` / `304`，配合浏览器 IndexedDB
- 冷数据定时清理（`COLD_DATA_RETENTION_DAYS`，默认 30）：只删终态 `ql_jobs`、过期 `ql_upload_batches`、终态 `ql_ai_analyses`；**不删** `ql_transactions` / `ql_reviews` / `ql_documents` / `ql_reports`

## 4. 操作记录

### `GET /api/admin/audit`

仅管理员，服务端分页，默认 20 条/页，最大 100。

| 参数 | 说明 |
| --- | --- |
| `page` | 从 1 开始 |
| `page_size` | 默认 20，最大 100 |
| `action` | 动作代码，只接受白名单；未知值被忽略，不拼 SQL |
| `user_id` | 按成员筛选 |
| `q` | 搜索成员显示名、动作代码或详情，最长 120 |
| `from` / `to` | ISO 时间，`from` 含、`to` 不含 |

响应含 `events`（每项带 `action_label`、`category`、`display`、`customer_name`、`detail_label`；`detail` 仍是原始写入值供排查）、`count`（当前筛选总数）、`page`、`page_size`、`actions`（服务端维护的动作白名单，前端不再硬编码中文）。默认 `seq DESC`。管理页「客户 / 详情」列只展示 `customer_name` 与 `detail_label`（如 `team:2` →「团队空间」，`…/report.html` →「网页报告」）。

**空间硬边界**（不由查询参数控制）：团队空间只返回本团队事件；个人/平台空间只返回当前用户自己的事件。

### 写入白名单

`Store.event` → `auditShouldPersist` 是唯一闸门，只有下列动作落库：

| 类别 | action |
| --- | --- |
| account | `login`（留存 30 天）、`change_password`、`enable_space` |
| customer | `create_customer`、`upload_queued`、`confirm_ownership`、`confirm_period`、`update_rules`、`review_transactions`、`submit_review`、`report_queued`、`download_report`、`job_cancelled` |
| admin | `add_user`、`toggle_user`、`change_grant` |

不在表内的（含 `switch_space`、`view_original*`、`*_finished`、`ai_analysis_*`、`job_timeout`）**一律不写库**。任务进度和 AI 状态看 `ql_jobs` / `ql_ai_analyses`，不靠操作记录复述。

留存：进程内小时级 `purgeAuditEvents` 删历史噪音与超龄行，启动先跑一轮；`AUDIT_RETENTION_DAYS`（默认 90）、`AUDIT_LOGIN_RETENTION_DAYS`（默认 30）。

### 工作台运维桥接

数据**仍只在清流** `ql_events`。工作台运维中心通过服务间凭证代理：

| 方向 | 路径 | 鉴权 |
| --- | --- | --- |
| 清流对外 | `GET /api/service/audit`、`POST /api/service/audit/purge` | `X-Service-Client` / `X-Service-Secret` = `WORKBENCH_SERVICE_*` |
| 工作台对外 | `GET/POST /api/v1/admin/ops/qingliu-audit*` | 平台 JWT；读跟 `api.logs.read`，清理另需 `api.ops.retention.write` |

不把 `ql_events` 迁进工作台库。

## 5. 索引

`ql_events` 需要 `INDEX(user_id,seq)`、`INDEX(action,seq)`、`INDEX(created,seq)`、`INDEX(space_kind,space_id,seq)`。新库由 `schema.sql` 创建；已有库执行 `migrations/001-audit-indexes.sql` 与 `006-event-space.sql`，执行前备份。

## 6. 验证

```bash
cd server && go test ./... && go vet ./...
cd ../frontend && pnpm check && pnpm smoke
```

真实环境回归：

1. `/admin` 操作记录每页 20 条、总数与翻页正确；切换类型/搜索后页码回到 1
2. 离开再返回 `/admin`，15 秒内不重复请求；点「刷新」绕过缓存
3. 新增/启停成员后，成员与操作记录均刷新
4. 切换空间、翻原件后 `ql_events` 不再新增对应行
5. 操作列显示中文标签，不出现 `switch_space` / `ai_analysis_finished` 裸码

## 7. 明确不做

- 不把操作记录做成通用日志仓或 ELK
- 不把任务进度二次抄进 `ql_events`
- 不为噪音动作补「展示但不入库」的双轨
- 不在单进程之外再引一层服务端缓存
