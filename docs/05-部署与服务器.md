# 05 · 部署与服务器

> 真实主机、账号、密钥见本地 `.secrets/SERVER-INFO.md` 和 `.secrets/DEPLOY-SECRETS.txt`。这两个文件不提交。本文用 `$QINGLIU_HOST` 等变量代替真实值。

## 1. 生产拓扑

```text
浏览器
  └─ HTTPS qingliu.example.com
       └─ Nginx (TLS, 限流, 64MB, 130s)
            └─ 127.0.0.1:8787  qingliu (Go)
                 ├─ MySQL 8  qingliu.*
                 ├─ /var/lib/qingliu  加密原件/报告
                 └─ HTTPS WORKBENCH_BASE_URL  工作台后台（登录/计费/订单）
```

同机还运行工作台后台（7720）和 MySQL；清流与它共用主机/Nginx，但不共用数据库、端口或进程。

## 2. 发布前

```bash
# 开发机
bash deploy/build.sh
# 产出：bin/qingliu-amd64、bin/qingliu-arm64、frontend/dist
```

构建脚本会执行前端 `npm ci && npm run build`、`go test ./...`、`go vet ./...`，然后交叉编译两个 Linux 架构。构建失败不要发布。

打包（不要带 `.secrets`、`.env`、客户资料）：

```bash
tar -czf /tmp/qingliu-release.tar.gz   bin/qingliu-amd64 frontend/dist fonts deploy docs licenses samples   README.md THIRD_PARTY_NOTICES.md SHA256SUMS
```

## 3. 发布

```bash
# 1) 备份（脚本会短暂停服，导出 DB + 数据目录）
ssh -i "$QINGLIU_SSH_KEY" root@"$QINGLIU_HOST" /usr/local/sbin/qingliu-backup.sh

# 2) 上传
scp -i "$QINGLIU_SSH_KEY" /tmp/qingliu-release.tar.gz root@"$QINGLIU_HOST":/tmp/

# 3) 服务器替换
ssh -i "$QINGLIU_SSH_KEY" root@"$QINGLIU_HOST" 'bash -s' <<'REMOTE'
set -euo pipefail
TS=$(date -u +%Y%m%d-%H%M%S)
rm -rf /tmp/qingliu-new && mkdir -p /tmp/qingliu-new
tar -xzf /tmp/qingliu-release.tar.gz -C /tmp/qingliu-new
cp /opt/qingliu/qingliu /opt/qingliu/qingliu.bak-$TS
systemctl stop qingliu

# 注意：服务 ExecStart 是 /opt/qingliu/qingliu，不是 /opt/qingliu/bin/qingliu-amd64
install -m 755 /tmp/qingliu-new/bin/qingliu-amd64 /opt/qingliu/qingliu
rsync -a --delete /tmp/qingliu-new/frontend/dist/ /opt/qingliu/frontend/dist/
rsync -a /tmp/qingliu-new/fonts/ /opt/qingliu/fonts/

systemctl start qingliu
sleep 2
curl -fsS http://127.0.0.1:8787/health
REMOTE
```

> 曾经踩过的坑：只更新 `/opt/qingliu/bin/qingliu-amd64` 不会生效；systemd 实际执行的是 `/opt/qingliu/qingliu`。静态 SVG 资源也由 Go 服务提供，新增根目录资源要检查 `server/main.go` 的 `.svg` 分支。

## 4. 回滚

```bash
systemctl stop qingliu
cp /opt/qingliu/qingliu.bak-<时间戳> /opt/qingliu/qingliu
# 如涉及前端，恢复对应 dist 快照；数据库按备份恢复
systemctl start qingliu
curl -fsS http://127.0.0.1:8787/health
```

数据库结构不兼容时，必须先按版本恢复数据库，不能只回退二进制。`VAULT_KEY` 不变才能解密旧文件。

## 5. Nginx 关键配置

- 80：仅 ACME + 301 到 HTTPS
- 443：TLS，反代 `127.0.0.1:8787`
- `/api/login` 单独 `limit_req`
- `client_max_body_size 64m`
- 读写超时 130s
- 安全头：HSTS、X-Content-Type-Options、Referrer-Policy、X-Frame-Options
- 业务不缓存；`/assets/` 带哈希长缓存

完整站点配置在服务器 `/etc/nginx/sites-available/qingliu.bujiaban.top.conf`；不要改其他站点。

## 6. 数据库

```sql
CREATE DATABASE qingliu CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'qingliu'@'localhost' IDENTIFIED BY '...';
GRANT SELECT,INSERT,UPDATE,DELETE,CREATE,INDEX,REFERENCES ON qingliu.* TO 'qingliu'@'localhost';
```

生产 DSN、账号、口令在 `/etc/qingliu/qingliu.env`，权限 0600。不要用 root 跑应用。

## 7. 备份

```bash
/usr/local/sbin/qingliu-backup.sh
ls -lh /var/backups/qingliu/
```

同时备份：MySQL `qingliu`、`/var/lib/qingliu`、`VAULT_KEY`。每日 03:30，保留 30 天；本机备份不防主机损坏，异地备份仍是待办。

恢复要点：

1. `systemctl stop qingliu`
2. 重建库并导入 `.sql.gz`
3. 解包 `qingliu-data-*.tar.gz` 到 `/var/lib`
4. `chown -R qingliu:qingliu /var/lib/qingliu && chmod 700`
5. 用同一恢复点的 `VAULT_KEY`
6. 启动并 `curl /health`

## 8. 证书

`/etc/letsencrypt/live/qingliu.bujiaban.top/`，webroot 续期，Nginx reload 钩子；`certbot renew --dry-run` 验证。到期日见服务器 `certbot certificates`。

## 9. 发布后验收

- `/health` 返回 ok
- HTTPS 登录成功，Cookie 带 Secure/HttpOnly/SameSite=Lax
- 首页/底稿/充值/移动端无 console error
- 上传合成 CSV 能解析；任务能排队/完成
- 充值页能加载套餐、创建订单、显示二维码/倒计时
- 旧报告仍可下载，`VAULT_KEY` 未变
- `/api/spaces` 未登录返回 401（不是 500）；登录后返回空间列表
- 空间切换后客户列表/余额/操作记录都换视角，刷新页面不回到旧空间

## 10. 环境与域名（**别弄反**）

| 环境 | 域名后缀 | 工作台 | 清流 | 主机 |
|---|---|---|---|---|
| **生产** | `bujiaban.top` | `https://worker.bujiaban.top` | `https://qingliu.bujiaban.top` | `115.191.68.41` |
| **测试** | `no996ai.cn` | `https://worker.no996ai.cn` | 尚未单独部署 | `118.196.106.85` |

- 清流生产与工作台生产**同机同环境**：`/etc/qingliu/qingliu.env` 的 `WORKBENCH_BASE_URL` 必须是 `https://worker.bujiaban.top`。
  2026-11-09 之前它指向 `worker.no996ai.cn`（测试），导致登录/充值/扣费落到测试库；已在当日改回，旧文件备份为 `/root/qingliu.env.bak-<时间戳>`。
- 改这个地址后必须**重新登录**：`ql_workbench_accounts` 里的 token 属于旧库，且账号必须存在于目标工作台库。
