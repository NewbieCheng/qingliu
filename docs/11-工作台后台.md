# 11 · 工作台后台（清流依赖）

清流不是孤立系统：登录、套餐、支付订单、积分余额、企业成员都依赖工作台后台。**后台源码不在本仓库**。

## 2. 两套环境（别搞混）

| 环境 | 域名 | 主机 | 说明 |
| --- | --- | --- | --- |
| **生产** | `worker.bujiaban.top` | 115.191.68.41 | 与清流生产同机；已配微信支付 |
| **测试** | `worker.no996ai.cn` | 118.196.106.85 | 无微信支付配置，只有 `manual` 渠道 |

## 4. 给工作台造账号必须三件事

不能只写 `t_user`：

1. `t_user`（密码哈希只认 `$argon2id`，bcrypt 一律判错）
2. `t_user_service`（`qingliu` / `workbench` 各一条，`status=1`）——工作台判断「这个账号能用哪个产品」读的是这张表，**不是** `t_user.service_code`
3. 用 `auth.HashPassword` 重新生成哈希

缺任一项，登录返回 `AUTH_SERVICE_SCOPE_MISMATCH`。

## 5. 套餐

**唯一入口：后台 → 平台 → 套餐规划**。套餐用工作台现有 `t_payment_sku` 表，清流没有自己的套餐表/接口/配置页。一个套餐可同时发布到 `workbench` 和 `qingliu`，同一 `metadata.plan_code` 分组、不同 `service_code` 一行。

当前 99 元/月套餐：

| SKU | service_code | 金额 | 积分 | 周期 |
| --- | --- | --- | --- | --- |
| `ql-monthly-99` | `qingliu` | 9900 分 | 9900 | 30 天 |
| `monthly-99-workbench` | `workbench` | 9900 分 | 9900 | 30 天 |

`¥99/月` 是 **30 天有效期，不是自动续费**；文案必须如实表达。

清流 `GET /api/billing/skus` → 工作台 `GET /api/v1/payment/skus?service_code=qingliu`，只显示 `qingliu` 的 SKU；下架后不再返回。

## 6. 支付订单

`POST /api/billing/orders` 由清流代理到工作台。状态：`pending`（待支付，返回 `code_url`）、`paid`、`closed`、`failed`。

二维码不是图片文件：`code_url` 存在工作台 `t_payment_order.code_url`，前端用 qrcode 库重新生成。刷新/换设备后：拉最近订单 → 找未过期 `pending` + `code_url` → 自动恢复结算卡 → 重新生成二维码。订单列表里也有「继续支付」。

**过期**：默认 `PAYMENT_ORDER_TTL=30m`（可配 5m–2h），同时写微信 Native `time_expire` 和本地 `expires_at`；前端显示「有效期至 + 剩余 mm:ss」，最后 5 分钟提示；后台每分钟关闭过期 pending 并清空 `code_url`；用户打开已过期订单时后端本地关闭并返回 `closed`。

**防重复下单**：创建前查同账号、同服务、同 SKU、未过期的 pending 订单，有就复用。连点「立即充值」应返回同一 `order_no`。

**清理**：`paid` 永不删；只清 `closed`/`failed`，保留 7 天且每账号最多最近 20 笔；每天清理，单次最多 1000 行。

以上都在工作台实现，清流只透传和展示。

## 7. 环境陷阱

生产清流 → `worker.bujiaban.top`；测试清流（未部署）→ `worker.no996ai.cn`。两套后台都要核对：

- `schema_migrations` 当前版本
- 对应环境里 `service_code=qingliu` 的 SKU 存在且 `active=1`、`hidden=0`
- 支付渠道：生产 `wechat_native`；测试没有微信商户参数，SKU 的 `provider` 要用 `manual`（管理员标记已支付），否则下单返回「支付未配置」

否则会出现：套餐能看到但下单失败、订单落到另一套库、二维码/回调不一致。

## 8. 发布

后台有自己的发布流程，**不要从清流仓库直接改后台生产**：

```bash
cd 不加班智能团后端
go test ./... && go build ./cmd/server
cd web/admin && pnpm install && pnpm build
```

发布前核对：

```sql
SELECT MAX(version) FROM schema_migrations;
SELECT code,service_code,amount_fen,active FROM t_payment_sku;
```

## 9. 模型

清流 AI 文档分析不单独配置模型；调用工作台网关的默认 chat/vision 模型。后台「AI 能力」页是模型配置唯一入口。

## 10. 验收

1. 充值页显示 ¥99/月
2. 点击两次 → 同一订单号
3. 二维码 + 有效期 30 分钟
4. 刷新页面 → 二维码恢复
5. 过期订单显示已过期，二维码隐藏
6. 支付回调查询 → paid，积分/账本增加
7. 已支付订单不会被清理

## 11. 交接注意

- 后台和服务器的密码/微信商户参数在后台生产环境文件，不在清流 `.secrets`
- 不要在两套库之间直接复制订单；订单属于实际支付环境
- 后台管理页与清流站点共用 115 的 Nginx，但站点配置独立，不要改错 server block
- 后台发布后要同时验证清流登录和充值页，避免 service secret/接口变更导致清流 401/503
