# 01 · 前端开发

## 1. 技术栈与入口

- React 19.2、Vite 7、原生 CSS（无组件库、无状态管理框架）
- `frontend/index.html` 挂载 `#root`
- `frontend/src/main.jsx` 只负责挂载，应用总装在 `src/app/App.jsx`
- 路径别名 `@` 指向 `frontend/src`
- 构建：`npm ci --ignore-scripts && npm run build`，产物在 `frontend/dist`
- 开发服务器：`npm run dev`（127.0.0.1:5173），`/api`、`/health` 已代理到生产后端

## 2. 目录结构

```text
src/
  main.jsx                   只挂载 React
  app/
    App.jsx                  登录守卫、路由分派、Shell 接线
    routes.jsx               唯一路由表
    ChangePasswordDialog.jsx
    ErrorBoundary.jsx
  pages/                     页面组合层，只拼装 feature
    login/ clients/ case/ recharge/ profile/ admin/ not-found/
  features/                  业务域
    auth/ clients/ case/ billing/ ai-analysis/ profile/ admin/
  shared/                    与业务无关的公共能力
    api/client.js            唯一 HTTP 客户端
    router/                  pushState 路由、Link、matchPath
    layout/                  Shell / Sidebar / Topbar / 导航配置
    ui/                      通用组件、图标、Toast、Loading
    hooks/ lib/ styles/      通用 Hook、格式化、设计令牌
```

依赖方向固定为：

```text
app → pages → features → shared
```

约束：

- `shared` 不能引用 `features` 或 `pages`
- feature 内部用相对路径；跨 feature 只能引用对方的 `index.js`
- 页面不能直接 `fetch` 或引用 `shared/api/client.js`，必须调用 feature 的 api
- 内部跳转必须使用 `navigate()` / `<Link>`，不能整页刷新
- 金额、日期、角色名、状态文案只在 `shared/lib` 或各 feature 的 `constants.js` 定义一次

`npm run check:arch` 会自动检查以上边界。

## 3. 路由

`src/app/routes.jsx` 是唯一路由表：

```js
{ path: "/clients/:cid", page: CasePage, title: "客户底稿" }
{ path: "/admin", page: AdminPage, roles: ["admin"] }
```

路由表支持：登录守卫、角色守卫、路径参数、404、页面标题。底部导航配置在
`src/shared/layout/navigation.js`，新增页面时同时改路由表和导航（如果需要在侧栏出现）。

客户底稿步骤同步到 URL：

```text
/clients/:cid?step=upload
/clients/:cid?step=ownership
/clients/:cid?step=review
/clients/:cid?step=report
```

刷新、返回、复制链接都不会丢失当前步骤。统计范围和交易筛选仍是页面内状态。

## 4. 请求、查询与缓存

- 网络请求经 `shared/api/client.js`；查询编排和 TTL 在 `app/queries/index.js`
- 浏览器内存缓存原语在 `shared/api/cache.js`，不落 localStorage，刷新即清空
- 列表使用服务端分页；相同查询在 TTL 内复用，手动刷新传 `force: true`
- 写操作成功后只失效相关前缀；退出和 401 清空全部缓存
- 操作记录走 `GET /api/admin/audit`，默认 20 条/页，支持动作、成员、搜索、时间筛选
- 详细策略、接口与失效表见 [`12-查询与缓存.md`](12-查询与缓存.md)

## 5. 请求与登录态

- `src/shared/api/client.js` 是唯一网络入口：自动带 CSRF、处理 JSON/FormData、抛 `ApiError`、统一 401 跳登录
- `src/features/*/api.js` 只描述业务接口，不弹 Toast、不改页面状态
- `src/features/auth/AuthProvider.jsx` 统一管理 `user`、CSRF、登录、退出、会话恢复
- 页面通过 `useAuth()` 读取登录态，不要各自请求 `/api/me`

401 的行为：`AuthProvider` 清空用户并 `navigate("/login")`，不会再整页刷新。

## 6. Shell 与登录页

- `shared/layout/WorkspaceShell.jsx`：组合 Sidebar、Topbar、正文和页脚
- `Sidebar`：品牌、分组导航、用户区；折叠状态存 `localStorage`
- 登录页在 `pages/login` + `features/auth/components`
- 左侧深松绿品牌区、右侧凭证区；移动端 860px 以下只显示右侧

## 7. 页面与组件

### 客户档案 `/`
`ClientsPage` + `features/clients`：列表、搜索、分页、新建客户弹窗。

### 客户底稿 `/clients/:cid`
`CasePage` 只负责组织流程，具体拆为：

- `useCaseData`：加载、轮询、错误、批量选中
- `UploadStep`、`OwnershipStep`、`ReviewStep`、`ReportStep`
- `TransactionTable`、`BulkReviewForm`、`CoverageForm`
- `RuleEditor`、`OriginalEvidenceDialog`、`ReportStep` 内报告版本
- `CaseAdminGrant`：管理员分配客户权限

新增底稿功能时优先加独立组件或 feature，不要重新堆回 `CasePage`。

### 充值 `/recharge`
`RechargePage` + `features/billing`：套餐、下单、二维码、倒计时、订单恢复、积分流水。
订单时间判断统一在 `features/billing/lib/order.js`。

### 个人信息 `/profile`
`ProfilePage`：资料展示、修改密码、充值入口、退出。

### 管理 `/admin`
`AdminPage` + `features/admin`：成员启停、新增成员、操作记录；仅管理员可进。

## 8. 公共 UI

`shared/ui` 提供：

- `PageHeader` / `SectionTitle`
- `Form` / `Field` / `FormRow` / `Select`
- `Modal`
- `StatusBadge`
- `EmptyState`
- `Pagination`
- `Loading`
- `UploadDropzone`
- `ToastHost` 与 `toast()`
- 全部 SVG 图标集中在 `icons.jsx`

`Form` 成功/失败统一走右上角 Toast；不要在表单里恢复内联“已保存”或原始错误条。
需要自己处理提示时传 `success=""`。

## 9. 样式

- `shared/styles/tokens.css`：设计令牌（颜色、布局、表面）
- `shared/styles/legacy.css`：现有视觉与响应式规则，保留原级联顺序
- `shared/styles/index.css`：统一入口

新增样式优先使用现有令牌和类名；大范围改版前先补 token，不要在页面里散落硬编码颜色。
移动端基线是 390px，不允许横向溢出。

## 10. 工程命令

```bash
npm run dev          # 本地开发
npm run lint         # ESLint
npm run check:arch   # 目录边界检查
npm run test         # Vitest
npm run build        # 生产构建
npm run check        # lint + 边界 + test + build
npm run smoke        # Playwright 浏览器冒烟（需要本机 Chromium）
```

`npm run smoke` 使用本机 Playwright Chromium，若路径不同请修改 `scripts/smoke.mjs` 的
`executablePath`。它 mock 了 `/api`，只验证路由、渲染、SPA 跳转和 390px 布局，
不能替代真实接口回归。

## 11. 修改清单

1. 改组件/样式后执行 `npm run check`
2. 涉及真实接口时按 `docs/10-本地开发与测试.md` 做浏览器回归
3. 改动路由/登录/底稿流程后至少跑一次 `npm run smoke`
4. 发布时重新构建 `frontend/dist`，不能只改产物
