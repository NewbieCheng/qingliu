# 01 · 前端开发

## 1. 技术栈与入口

- React 19.2、Vite 7、原生 CSS（无组件库、无状态管理框架）
- `frontend/index.html` 挂载 `#root`；`src/main.jsx` 只负责挂载
- 路径别名 `@` → `frontend/src`；包管理器 **pnpm**
- 构建 `pnpm build` → `frontend/dist`
- 开发服务器 `pnpm dev` → `127.0.0.1:5173`，`/api`、`/health` 代理到本机清流 `127.0.0.1:8787`

## 2. 目录与依赖方向

```text
src/
  main.jsx                   只挂载 React
  app/                       App.jsx、routes.jsx、queries/index.js、ChangePasswordDialog、ErrorBoundary
  pages/                     login/ clients/ case/ recharge/ profile/ admin/ not-found/
  features/                  auth/ clients/ case/ billing/ ai-analysis/ profile/ admin/
    <domain>/                api.js · index.js · components/ · constants.js · hooks/ · lib/
  shared/                    api/ router/ layout/ ui/ hooks/ lib/ styles/
    api/client.js            唯一 HTTP 客户端
    api/cache.js             内存缓存原语（Map + TTL）
    layout/                  WorkspaceShell / Sidebar / Topbar / MobileTabBar / navigation.js
    ui/                      通用组件、icons.jsx、toast-api.js
```

依赖方向固定 `app → pages → features → shared`，`pnpm check:arch` 自动检查（`shared` 不引 `features`/`pages`、页面不直接 `fetch`/引 `client.js`、跨 feature 只走 `index.js`、内部跳转不用整页刷新）。

## 3. 路由与导航

`src/app/routes.jsx` 是唯一路由表，支持登录守卫、角色守卫、路径参数、404、页面标题：

```js
{ path: "/clients/:cid", page: CasePage, title: "客户底稿" }
{ path: "/admin", page: AdminPage, title: "团队与权限", roles: ["admin"] }
```

侧栏与手机底部 Tab 在 `shared/layout/navigation.js`（`NAVIGATION` / `MOBILE_PRIMARY_TABS` / `MOBILE_ME_PATHS`）；≤680px 走底部 Tab +「我的」面板。新增页面时同时改路由表和导航。

底稿步骤同步到 URL，刷新、返回、复制链接都不丢：`?step=upload|ownership|review|report`。统计范围和交易筛选仍是页面内状态。

## 4. 请求、查询与缓存

- 网络请求经 `shared/api/client.js`（唯一入口：CSRF、JSON/FormData、`ApiError`、统一 401 跳登录）
- `features/*/api.js` 只描述业务接口，不弹 Toast、不改页面状态
- 查询编排与 TTL 在 `app/queries/index.js`；缓存原语在 `shared/api/cache.js`，不落 localStorage
- 列表一律服务端分页；TTL 内复用，手动刷新传 `force: true`；写成功后只失效相关前缀，退出/401/切空间清空全部
- `AuthProvider` 统一管理 `user`、CSRF、登录、退出、会话恢复；页面用 `useAuth()`，不要各自请求 `/api/me`

TTL 与失效表见 [12](12-查询缓存与操作记录.md)。

## 5. Shell 与登录页

- `WorkspaceShell` 组合 Sidebar、Topbar、正文和页脚；`Sidebar` 折叠状态存 `localStorage`
- 登录页在 `pages/login` + `features/auth/components`：左侧深松绿品牌区、右侧凭证区；860px 以下只显示右侧
- 登录需要工作台图形验证码（`GET /api/auth/captcha` 代理），缺了会被拒，**不是**登录失败

## 6. 页面

| 路由 | 组成 | 要点 |
| --- | --- | --- |
| `/` | `ClientsPage` + `features/clients` | 列表、搜索、分页、新建客户弹窗 |
| `/clients/:cid` | `CasePage` + `useCaseData`、`UploadStep`、`OwnershipStep`、`ReviewStep`、`ReportStep`、`TransactionTable`、`BulkReviewForm`、`CoverageForm`、`RuleEditor`、`OriginalEvidenceDialog`、`TaskList`、`CaseAdminGrant` | `CasePage` 只组织流程，新功能加独立组件，不要堆回去 |
| `/recharge` | `RechargePage` + `features/billing` | 套餐、下单、二维码、倒计时、订单恢复、积分流水；时间判断在 `lib/order.js` |
| `/profile` | `ProfilePage` | 资料、改密、空间切换、充值入口、退出 |
| `/admin` | `AdminPage` + `features/admin` | 成员启停、新增成员（调工作台开户）、操作记录；仅管理员 |

**空间切换**（`features/profile/components/SpaceSwitcher.jsx`，由 `app/App.jsx` 作为 `spaceSwitcher` 插槽注入 Shell）：数据来自 `GET /api/spaces`（`querySpaces`，TTL 15s）；只有一种空间时不显示切换按钮——可点却无意义的按钮只会让人困惑。切换成功后必须 `invalidateAll()` + `window.location.reload()`：空间变了，客户列表/余额/操作记录全换视角，只刷当前页会让首页继续显示上一个空间的客户（比报错更糟）。这是全站唯一允许整页重载的地方（`ErrorBoundary` 的「重试」除外）。

> 空间切换是业务能力，因此放在 `features/profile`；`shared/layout` 只留一个 `spaceSwitcher` 渲染插槽，**不得**反向 import `features`（`pnpm check:arch` 会拦）。

## 7. 公共 UI 与样式

`shared/ui` 提供 `PageHeader` / `Form` / `FormRow` / `Select` / `Modal` / `ModalActions` / `Badge` / `EmptyState` / `Pagination` / `Loading` / `UploadDropzone` / `SearchInput` / `SegmentedControl` / `Switch` / `FoldPanel` / `InputWithCheck` / `ToastHost` 与 `toast()`；全部 SVG 图标集中在 `icons.jsx`。

`Form` 成功/失败统一走右上角 Toast；不要在表单里恢复内联「已保存」或原始错误条，需要自定义时传 `success=""`。

样式：`styles/tokens.css`（设计令牌）、`legacy.css`（既有视觉与响应式，保留原级联顺序）、`auth.css`（登录/注册）、`index.css`（唯一入口，被 `main.jsx` 引入）。新增样式优先用现有令牌和类名，不散落硬编码颜色；大范围改版前先补 token。移动端基线 390px，不允许横向溢出。

## 8. 工程命令

```bash
pnpm dev          # 本地开发 5173
pnpm lint         # ESLint
pnpm check:arch   # 目录边界检查
pnpm test         # Vitest
pnpm build        # 生产构建
pnpm check        # lint + 边界 + test + build
pnpm smoke        # Playwright 冒烟（需本机 Chromium，mock 了 /api）
```

`pnpm smoke` 只验证路由、渲染、SPA 跳转和 390px 布局，不能替代真实接口回归。

## 9. 修改清单

1. 改组件/样式后执行 `pnpm check`
2. 涉及真实接口时按 [10](10-本地开发与测试.md) 做浏览器回归
3. 改路由/登录/底稿流程后至少跑一次 `pnpm smoke`
4. 发布时重新构建 `frontend/dist`，不能只改产物
