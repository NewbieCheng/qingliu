> 日期：2026-11-21
> 回应用户两个问题：①「OCR/AI 出来的东西跟后面流程不匹配时怎么办」②「登录只显示认证失败，用户不知道所以然」

## 一、兜底链路契约化（问题①）

### 改动前：双重转换损耗

```
原文/OCR → AI 输出「像表格的文本」→ 规则再猜一遍列在哪 → 结构化行
                                  ↑ 猜不中就全废
```

AI 已经理解了内容，却要它输出文本表格，再用规则去猜版式。这是「跟后面不匹配」的根因。

### 改动后：显式 JSON 契约 + 三级降级

```
① AI 直接输出结构化 JSON  → 直接反序列化（不需要猜列位置）
      ↓ JSON 不可用
② 退回「表格文本」解析    → 兼容老模型 / 老提示词
      ↓ 两条都不行
③ 明确原因上报 → AI 导诊翻译成人话 → 用户在页面上看到可点按钮
```

### 代码位置

| 环节 | 函数 | 作用 |
| --- | --- | --- |
| 提示词 | `structureRescuePrompt` | 要求输出 `{"source","rows":[{date,direction,amount,...}]}` |
| 解析 | `parseRescueJSON` | 三级容错：直接解析 → 去 Markdown 围栏 → 截取 `{...}` |
| 归一 | `rowsFromJSON` + `directionWord` | 英文档位 `income/expense/neutral` → 中文方向词 |
| 采纳 | `applyStructureRescueResult` | 先 JSON，后表格文本，都失败给出双路原因 |
| 安全阀 | 同函数 | AI 结果不如规则时保留原结果 |
| **原因上报** | `tryStructureRescueAfterOCR` | 失败原因写入 `meta.issues` + `meta.rescue_failed` |

### 关键修复：失败原因不再只进日志

之前兜底失败只 `log.Printf`，用户永远看不到。现在写入 `meta.issues`，Stage 4 的 `explainIssue` 会把它交给 AI 翻译成用户看得懂的话 + 可点按钮。

### 实测

| 日期 | 方向 | 金额 |

## 二、登录错误可诊断（问题②）

### 根因

用户看到的「认证失败」来自上游的 `AUTH_UNAUTHORIZED`，它把**密码错误、账号不存在、令牌问题**全压成一句话。用户无法判断该改密码、该等一会儿，还是该找客服。

### 后端改动

`internal/auth/handler.go`：
- 新增 `loginPublicError()` / `writeLoginError()`，仅用于登录端点
- `ErrInvalidCredentials` → 独立错误码 `AUTH_INVALID_CREDENTIALS` + 「账号或密码不正确」
- 安全边界：**不区分「账号不存在」与「密码错误」**（防枚举），但码可辨

### 清流改动

`server/workbench.go` 新增 `wbLoginError()`，按上游错误码翻译成可行动中文（覆盖 14 种）：

| 上游错误码 | 用户看到的提示 |
| --- | --- |
| `AUTH_INVALID_CREDENTIALS` / `AUTH_UNAUTHORIZED` | 账号或密码不正确 |
| `AUTH_CAPTCHA_REQUIRED` | 本次登录需要图形验证码，请点验证码后重试 |
| `AUTH_CAPTCHA_INVALID` | 图形验证码错误或已过期，请刷新后重试 |
| `AUTH_ACCOUNT_LOCKED` | 密码错误次数过多，账号已临时锁定，请 N 分钟后再试 |
| `AUTH_ACCOUNT_FROZEN` | 账号已冻结，请联系管理员解冻 |
| `AUTH_ACCOUNT_DISABLED` | 账号已禁用，请联系管理员 |
| `AUTH_SERVICE_UNAUTHORIZED` | 清流服务与工作台的对接凭据失效，请联系管理员 |
| `AUTH_SERVICE_SCOPE_MISMATCH` | 该账号不属于清流服务，请用清流账号登录 |
| `AUTH_NO_SPACE_AVAILABLE` | 这个账号当前没有可进入的空间，请联系客服恢复 |
| `SESSION_SUPERSEDED` | 账号已在其他设备登录，请重新登录 |
| `AUTH_LOGIN_RATE_LIMITED` | 登录尝试过于频繁，请稍后再试 |
| `AUTH_VERIFICATION_INVALID` | 验证码无效或已过期，请重新获取 |
| `AUTH_ACCOUNT_NOT_FOUND` | 该账号尚未注册，请先注册或联系管理员 |

### 前端改动

`LoginForm.jsx`：遇到含「验证码」的错误时，**自动重新拉起验证码框**，并提示「验证码已填好，请再点一次登录」。之前只显示文字，用户看到「需要验证码」却找不到入口。

### 实测

| 场景 | 结果 |
| --- | --- |
| 本地 · 密码错误 | `401 {"error":"账号或密码不正确"}` |
| 本地 · 账号不存在 | `401 {"error":"账号或密码不正确"}`（防枚举，与上同句） |
| 本地 · 空密码 | `400 {"error":"请填写密码或邮箱验证码"}` |
| 本地 · 正确密码 | `200 {"ok":true}` |
| **生产 · 错误密码** | `{"error":"本次登录需要图形验证码，请点验证码后重试"}` |

> 生产实测还原了用户截图的那一刻：当时上游要求图形验证码，而旧代码统一显示「认证失败」，所以用户不知道发生了什么。

## 三、解析失败导诊区（页面调整）

`ParseDetailDialog` 之前只显示 `what` 和 `why`，**没有把可点按钮显示出来**。现在：

- 按 `verdict` 分色：失败红 / 存疑黄 / 正常绿
- 显示 `meta.explain.actions` 为可点按钮（重新识别 / 用解析工具 / 解密重传 / 重新上传）
- 显示 `meta.rescue_failed` 技术原因（AI 兜底失败的真因）
- 按钮接了实际动作（`onRequestReparse` 等），不是死按钮
