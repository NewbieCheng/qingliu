# 环境说明与部署流程

> 目的：**保证测试环境和生产环境永远跑同一份产物**，测试通过什么，上线就是什么。

---

## 一、两套环境

| | 测试 | 生产 |
| --- | --- | --- |
| 域名 | `https://qingliu-test.bujiaban.top` | `https://qingliu.bujiaban.top` |
| 服务名 | `qingliu-test.service` | `qingliu.service` |
| 端口 | `127.0.0.1:8789` | `127.0.0.1:8787` |
| 二进制 | `/opt/qingliu-test/qingliu` | `/opt/qingliu/qingliu` |
| 前端 | `/opt/qingliu-test/frontend/dist` | `/opt/qingliu/frontend/dist` |
| 配置 | `/etc/qingliu-test/qingliu-test.env` | `/etc/qingliu/qingliu.env` |
| 数据库 | `qingliu_test` | `qingliu` |
| 数据目录 | `/var/lib/qingliu-test` | `/var/lib/qingliu` |
| 证书 | 独立 Let's Encrypt | 独立 Let's Encrypt |
| 搜索引擎 | `noindex, nofollow` | 正常 |

**共用**：后端（`worker.bujiaban.top`）、工作台账号体系、`VAULT_KEY`。

> ⚠️ 两个环境共用同一套工作台身份。**测试时请用测试账号登录**：同一个账号在测试环境登录会刷新该账号的令牌，生产环境已存的会话会失效。

## 二、数据库隔离

- 测试用 `qingliu_test`，生产用 `qingliu`，**物理隔离**
- 表结构由程序启动时自动创建（测试库首次启动已自建 15 张表）
- 测试库初始为空：`ql_users=0`，生产 `ql_users=18`

**不要把生产数据往测试库同步**——测试就是为了验证"空环境 + 新数据"的行为。

## 三、一键部署（推荐）

```bash
./scripts/deploy.sh both    # 测试 + 生产（默认）
./scripts/deploy.sh test    # 只发测试
./scripts/deploy.sh prod    # 只发生产
```

脚本做的事：

1. **编译一次** linux/amd64 与前端
2. **上传一次**，并用 sha256 双向校验，传输损坏直接中止
3. 按 `test → prod` 顺序部署，各自：
   - 备份现有二进制与前端（每个环境各留最新一份）
   - 停服 → 替换 → 启服
   - 健康检查（`/health` 返回 200 才算成功，否则打印日志并退出）
   - 清理旧备份
4. 收尾输出两个环境的 sha256，**必须一致**

### 为什么必须"同一份产物"

以前测试和生产各编各的，测试通过的东西上线后行为不一致。现在从源头保证：一次编译，同一个哈希发到两个环境。

## 四、手动部署（应急）

```bash
# 编译
cd server && CGO_ENABLED=0 GOOS=linux GOARCH=amd64 \
  go build -trimpath -ldflags="-s -w" -o /tmp/ql.bin .
cd ../frontend && pnpm build

# 上传
scp -i ~/.ssh/no996_prod_ed25519 /tmp/ql.bin root@115.191.68.41:/tmp/ql.bin
ssh root@115.191.68.41 "rm -rf /tmp/qd && mkdir -p /tmp/qd"
scp -i ~/.ssh/no996_prod_ed25519 -r frontend/dist/. root@115.191.68.41:/tmp/qd/

# 校验哈希（必须一致）
sha256sum /tmp/ql.bin
ssh root@115.191.68.41 "sha256sum /tmp/ql.bin"

# 替换（以生产为例；注意先停服，否则 Text file busy）
ssh root@115.191.68.41 '
  TS=$(date +%Y%m%d-%H%M%S)
  cp /opt/qingliu/qingliu /opt/qingliu/qingliu.bak-$TS
  systemctl stop qingliu.service
  cp /tmp/ql.bin /opt/qingliu/qingliu && chmod +x /opt/qingliu/qingliu
  rm -rf /opt/qingliu/frontend/dist.n && mkdir -p /opt/qingliu/frontend/dist.n
  cp -a /tmp/qd/. /opt/qingliu/frontend/dist.n/
  rm -rf /opt/qingliu/frontend/dist && mv /opt/qingliu/frontend/dist.n /opt/qingliu/frontend/dist
  systemctl start qingliu.service
  sleep 5 && systemctl is-active qingliu.service
  curl -sf -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8787/health
'
```

> `cp` 覆盖正在运行的二进制会报 `Text file busy`，**必须先 stop**。

## 五、回滚

```bash
# 生产
ssh root@115.191.68.41 '
  systemctl stop qingliu.service
  cp /opt/qingliu/qingliu.bak-<TS> /opt/qingliu/qingliu
  rm -rf /opt/qingliu/frontend/dist
  cp -a /opt/qingliu/frontend/dist.bak-<TS> /opt/qingliu/frontend/dist
  systemctl start qingliu.service
'
```

测试同理，把 `/opt/qingliu` 换成 `/opt/qingliu-test`、`qingliu.service` 换成 `qingliu-test.service`。

## 六、验证清单

部署后逐项确认（`./scripts/deploy.sh` 已自动做 1–3）：

| # | 检查 | 命令 |
| --- | --- | --- |
| 1 | 服务在跑 | `systemctl is-active qingliu[-test].service` |
| 2 | 后端健康 | `curl -sf http://127.0.0.1:878[79]/health` |
| 3 | 站点可达 | `curl -o /dev/null -w "%{http_code}" https://<域名>/` |
| 4 | 版本一致 | `sha256sum /opt/qingliu/qingliu /opt/qingliu-test/qingliu` |
| 5 | 数据隔离 | `mysql -uroot -N -e "SELECT COUNT(*) FROM qingliu_test.ql_users"` |
| 6 | 登录提示正常 | `curl -s -X POST https://<域名>/api/login -d '{"username":"x","password":"y"}'` |

第 4 项两个哈希**必须相同**，否则说明某一边没更新成功。

## 七、后端（不加班）部署

后端只有一套（`no996-backend.service`，`worker.bujiaban.top`），测试与生产**共用**。

```bash
cd ../不加班智能团后端
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 \
  go build -trimpath -ldflags="-s -w" -o /tmp/be.bin ./cmd/server

scp -i ~/.ssh/no996_prod_ed25519 /tmp/be.bin root@115.191.68.41:/tmp/be.bin
ssh root@115.191.68.41 '
  TS=$(date +%Y%m%d-%H%M%S)
  cp /opt/no996-backend/bin/server /opt/no996-backend/bin/server.bak-$TS
  systemctl stop no996-backend.service
  cp /tmp/be.bin /opt/no996-backend/bin/server
  chmod +x /opt/no996-backend/bin/server
  chown no996:no996 /opt/no996-backend/bin/server
  systemctl start no996-backend.service
  sleep 6 && systemctl is-active no996-backend.service
  curl -sf -o /dev/null -w "%{http_code}\n" https://worker.bujiaban.top/health/live
'
```

> 改后端会影响两个环境。**先后端、后清流**：清流依赖后端的 Responses 行为。

## 八、常见问题

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| `Text file busy` | 覆盖正在运行的二进制 | 先 `systemctl stop` |
| `bind: address already in use` | 端口被占 | `ss -lntp \| grep <端口>` 查占用者，改 env 里的 `LISTEN_ADDR` |
| 登录提示"对接凭据失效" | 服务凭据过期/错 | 检查 `/etc/qingliu[-test]/*.env` 的 `WORKBENCH_SERVICE_SECRET` |
| 测试环境登录后生产掉线 | 同账号双环境登录刷新令牌 | 测试用独立账号 |
| 502 | 后端没起来 | `journalctl -u qingliu[-test].service -n 50` |
