# 07 · 运维手册

## 日常检查

```bash
systemctl status qingliu
journalctl -u qingliu -n 100 --no-pager
curl -fsS http://127.0.0.1:8787/health
systemctl status nginx
mysqladmin ping
```

健康返回 `{"status":"ok"}`；只看到进程 active 不算健康。

## 日志

- 应用：`journalctl -u qingliu -f`
- Nginx：`/var/log/nginx/access.log`、`error.log`
- 备份：cron 日志 / `/var/backups/qingliu/`
- 不要记录密码、`VAULT_KEY`、工作台 token 或客户敏感字段

## 备份

```bash
/usr/local/sbin/qingliu-backup.sh
ls -lh /var/backups/qingliu/
```

备份包含 DB + 数据目录；脚本会短暂停服。保留 30 天。每月至少做一次恢复到临时库/临时目录的演练。

## 证书

```bash
certbot certificates
certbot renew --dry-run
systemctl reload nginx
```

证书到期前确认自动续期钩子仍存在。

## 磁盘/内存

```bash
df -h
free -h
du -sh /var/lib/qingliu /var/backups/qingliu
systemd-cgtop -1
```

清流上限：`MemoryMax=1G`、`CPUQuota=200%`、`GOMEMLIMIT=512MiB`。同机还有工作台后台/MySQL，需一起观察。

## 常见故障

| 现象 | 排查 |
| --- | --- |
| `/health` 503 | MySQL 是否可达、DSN/口令、连接数 |
| 登录 401 | 工作台 service 账号/密钥、账号是否停用；本地兜底是否可用 |
| 套餐 503 | `WORKBENCH_BASE_URL` 是否可达、SKU 是否存在 |
| 二维码不显示 | 订单是否 pending、`code_url` 是否为空、是否过期 |
| 上传 413 | Nginx `client_max_body_size` / 批次限制 |
| 报告 500 | 字体、`DATA_DIR` 权限、`VAULT_KEY`、任务日志 |
| 重启后任务不动 | `ql_jobs` 状态、执行器日志、MySQL 命名锁 |
| 静态资源 404 | 是否在 `dist`、Go 静态分支是否允许该扩展名 |

## 回滚

保留 `/opt/qingliu/qingliu.bak-<TS>` 和前端 dist 快照；数据库按备份点恢复。回滚后必须再跑 `/health` 和登录/充值验收。

## 安全事件

1. 停用相关账号/撤销会话
2. 保留日志，不要删除
3. 更换泄露凭据；`VAULT_KEY` 不能直接轮换，需先设计重加密
4. 通知负责人，按内部流程处理
