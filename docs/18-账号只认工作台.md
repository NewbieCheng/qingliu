# 18 · 账号只认工作台（清流不再做账号库）

> 2026-11-10。配套实现：`server/admin_members.go`、`migrations/007-grant-workbench-binding.sql`。

## 1. 目标模型

| 能力 | 真相在哪 | 清流本地还留什么 |
| --- | --- | --- |
| 登录 / 密码 / 启停 / 企业成员 | **工作台** `t_user` + `t_space_membership` + `t_user_service` | 无（只代理） |
| 清流产品权限码 | 工作台登录快照 → `ql_workbench_accounts.permissions` | 映射表 |
| 客户访问授权（业务员只能看被授权客户） | 清流 `ql_grants.workbench_user_id` | **唯一业务绑定** |
| 会话 Cookie | 清流 `ql_sessions` | 需要一个本地 subject id |

**清流不是第二套账号系统。** `ql_users` 只是登录时自动生成的**影子行**（给会话 / 任务 / 操作记录当外键），没有独立密码真相，也不能用来「开户」。

## 2. 客户可见性（团队空间）

- **管理员**（`qingliu.admin`）：看本企业全部客户。
- **非管理员**：只看 `ql_grants` 里绑了自己 `workbench_user_id` 的客户。
- **个人空间**：仍只看 `owner_user_id = 自己` 的客户（与工作台成员无关）。

## 3. 成员管理（仅管理员）

- 入口与 `/admin` 路由只认 `qingliu.admin`（`isQingliuAdmin`）；非管理员无导航、直链提示无权限。
- 成员列表**不展示当前登录账号**；服务端与前端都会过滤自己。
- 自己账号不可停用、不可删除（前后端双拦）。

## 4. 删除成员

清流「删除」= **移出当前企业**（工作台 `DELETE /tenant/members/:id`，团队空间置 removed）。

- 工作台 **个人账号保留**（`t_user` 不删），个人空间仍可登录。
- 清流清掉该人的客户授权与会话；影子行保留（审计外键）。
- 须输入操作者密码二次确认（工作台 `POST /auth/verify-password`，不改密、不撤令牌）。

## 5. 明确不做

- 不在清流再建本地账号库、不维护第二套密码。
- 不把 `ql_users` 物理删掉（会话 / 任务 / 事件外键还挂着）；职责降级为影子。
- 不把工作台 RBAC 再抄一份到清流表里。
- 不把「移出企业」做成工作台个人账号硬删。

## 6. 验收

1. 管理员看成员列表 = 工作台同企业成员 **减去自己**。
2. 非管理员看不到「团队与权限」入口；直链提示无权限。
3. 「新增账号」弹窗只调工作台开户；工作台账户管理能看到同一邮箱。
4. 「删除」需输管理员密码；成功后列表消失，工作台个人账号仍在。
5. 业务员登录后，未授权客户列表为空；管理员授权后可见。
