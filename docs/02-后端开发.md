# 02 · 后端开发

## 1. 形态

**一个 Go 进程**，标准库 `net/http`，不依赖 Web 框架、ORM、Redis、消息队列或第二个常驻进程。它同时提供 `/api/*` JSON、`/health`、同源 React 静态产物，并在进程内跑单执行器处理解析/报告/AI 分析。入口 `server/main.go`，模块名 `qingliu`，Go 1.26。

## 2. 启动配置

生产通过 `/etc/qingliu/qingliu.env` 注入（不提交真实值）。代码实际读取的变量：

| 变量 | 说明 |
| --- | --- |
| `MYSQL_DSN` | MySQL 8 DSN，专用库/用户 |
| `PUBLIC_ORIGIN` | 唯一外部源，不带末尾斜杠；决定 Cookie 是否 `Secure` |
| `VAULT_KEY` | 64 位 hex，AES-256-GCM 文件加密；不可随意更换 |
| `DATA_DIR` | 加密原件与报告目录 |
| `STATIC_DIR` | `frontend/dist`（默认同值） |
| `PDF_FONT` | 中文 PDF 字体 |
| `LISTEN_ADDR` | 默认 `127.0.0.1:8787` |
| `GOMEMLIMIT` / `GOMAXPROCS` | 资源约束（运行时读取） |
| `WORKBENCH_BASE_URL` | 工作台后台地址 |
| `WORKBENCH_SERVICE_CLIENT` / `WORKBENCH_SERVICE_SECRET` | service login 凭证 |
| `QINGLIU_ALLOW_LOCAL_LOGIN` | `1` 时允许本地密码兜底登录 |
| `AUDIT_RETENTION_DAYS` / `AUDIT_LOGIN_RETENTION_DAYS` | 操作记录留存，默认 90 / 30 |
| `COLD_DATA_RETENTION_DAYS` | 中间态冷数据保留，默认 30 |

`init-admin` 子命令额外读 `ADMIN_USERNAME` / `ADMIN_PASSWORD`；库里已有账号时初始化自动关闭。

启动执行 `schema.sql` 的 `CREATE TABLE IF NOT EXISTS`，不清空旧表，也**不会给已有表补列**——结构变更必须另做版本化迁移并手动执行。

## 4. 会话、空间与授权

- 登录生成随机会话 token 存 `ql_sessions`；Cookie `HttpOnly; Secure; SameSite=Lax`（HTTPS 时）
- 会话行带 `space_kind` / `space_id`（**本会话所在空间**），授权判定读它而不读用户上的列
- 每会话一个 CSRF token，前端从 `/api/me` 取，写请求带 `X-CSRF-Token`；业务响应 `Cache-Control: no-store`
- 登录失败按 IP+账号计数，5 次锁 15 分钟；Nginx 另有 `limit_req`
- 本地密码 bcrypt（仅 `QINGLIU_ALLOW_LOCAL_LOGIN=1` 可用）；工作台侧只认 argon2id
- 权限判定走 `q.can(code)`（读 `ql_workbench_accounts.permissions` 快照），`ql_users.role` 只是兜底
- 资料/报告用 AES-256-GCM 加密落盘，报告带 SHA256

`scopeWhere(access customerAccess, alias)` 是授权判定与列表查询的**唯一口径**：

| 情况 | 可见范围 |
| --- | --- |
| 团队 + 管理员 | 本企业全部客户（`workspace_tenant_id = 空间 id`） |
| 团队 + 非管理员 | 本企业**且** `ql_grants.workbench_user_id` 命中自己；无工作台 id 则 `1=0` |
| 个人/平台 + 已绑定工作台 | 自己创建的，或被授权给 `workbench_user_id` 的 |
| 个人/平台 + 未绑定 | 自己创建的，或被授权给本地影子 `user_id` 的 |

```go
// 团队 + 非管理员（节选）
return alias + ".workspace_tenant_id=? AND EXISTS (" +
    "SELECT 1 FROM ql_grants g WHERE g.customer_id=" + alias + ".id AND g.workbench_user_id=?)",
    []any{access.Space.ID, access.WBUserID}
```

平台空间刻意走「只看自己」：清流没有平台视图，平台令牌绝不放宽到某团队全部资料。管理员也不能跨企业——`role=="admin"` 无条件放行的旧漏洞已修掉。`Store.allowed` 与列表共用这份实现，否则会出现「列表看不到、直接输 ID 却能打开」的越权。

## 5. 工作台桥接

`loadWBConfig()` 读取 `WORKBENCH_BASE_URL`、`WORKBENCH_SERVICE_CLIENT`、`WORKBENCH_SERVICE_SECRET`。

- `POST /api/v1/service/auth/login`，body `{email, password, service_code:"qingliu", captcha_id, captcha_code}`，带 `X-Service-Client` / `X-Service-Secret`
  - **验证码是硬要求**：工作台在密码校验前就查，缺了返回 `AUTH_CAPTCHA_REQUIRED`（401）——不是登录失败
  - 账号必须在 `t_user_service` 里有 `qingliu` 且 `status=1`，否则 `AUTH_SERVICE_SCOPE_MISMATCH`（403）
- 拿到 token 后加密存 `ql_workbench_accounts`，同时存权限码快照 `permissions`
- 后续计费请求用 `Authorization: Bearer <access_token>`，过期用 refresh token 刷新
- 浏览器永远看不到 service secret 或工作台 token

### 5.1 工作台令牌与「请重新登录工作台账号」（Agent 必读）

| 层 | TTL | 存哪 |
| --- | --- | --- |
| 清流 Cookie `ql_session` | **8 小时** | `ql_sessions` |
| 工作台 access token | **默认 15 分钟**（后端 `defaultAccessTokenTTL`） | 加密进 `ql_workbench_accounts.access_token` |
| 工作台 refresh token | 约 30 天，**一次性轮换** | 加密进 `ql_workbench_accounts.refresh_token` |

用户症状：「清流还登着，充值/余额突然要重新登录工作台；大约一刻钟一次；本地也没人挤号」。  
根因**不是** Cookie 过期，也**不是**账号被别处登录，而是：

1. access 快过期时，`wbAccessToken` / `wbRequest(401)` 会调 `wbRefresh` → 工作台 `POST /api/v1/auth/refresh`。
2. 工作台 refresh **轮换**：旧 refresh 立刻作废；再拿旧的去刷 = `ErrRefreshTokenReused` → **吊销整个 family**（新 access/refresh 一起废）。
3. 充值页顶栏 `queryBalance` 与正文 `getSkus`/`getBalance` 等会**并发**打 `/api/billing/*`；到期窗口内若两次 `wbRefresh` 并行，就会自踢。
4. 清流 Cookie 仍有效，所以只看到业务接口 503「请重新登录工作台账号」（请求 id 形如 `r-xxxxxx`），其它工作台代理（空间名、成员、AI 上传）也会一起挂。

**硬约束（改 `workbench.go` 时）：**

- 同一本地 `user_id` 的 refresh 必须单飞（`App.refreshGates`）；禁止无锁并发 `wbRefresh`。
- 不要把工作台宕机/网络错误一律折叠成「请重新登录」；refresh 失败文案要区分（已有回归：`workbench_token_test.go`）。
- 不要把 access TTL 误当成清流会话 TTL；也不要靠前端轮询去「保活」refresh。
- 复现单测：`server/workbench_refresh_test.go`（并发复用吊销 family + singleflight 合并）。

## 6. 执行器

`ql_jobs` 记录 queued/running/done/failed，浏览器关闭不取消。单执行器用 MySQL 命名锁防多实例并发，进程退出后由 systemd 重启。解析/报告任务幂等，失败写 message 可重试。`sweepStaleJobs` 把超过 30 分钟仍未终态的任务标成失败，避免 `busy()` 永久挡住该客户。客户修改与后台处理用同一客户锁，处理期间阻止修改。`/tmp` 逐页 OCR，避免整份扫描件同时渲染。

## 8. 不要做

不引入第二个数据库/Redis/队列解决单机任务；不在浏览器存 service secret 或模型 Key；不改 `VAULT_KEY`、不绕过 `Store.seal/unseal` 写文件；不直接改线上表而不回写迁移；不写 `role == "admin"` 这类硬编码判定。
