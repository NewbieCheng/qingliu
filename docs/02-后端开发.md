# 02 · 后端开发

## 1. 形态

清流后端是**一个 Go 进程**，使用标准库 `net/http`，不依赖 Web 框架、Redis、消息队列或第二个常驻进程。它同时：

- 提供 `/api/*` JSON API
- 提供 `/health`
- 同源提供 `STATIC_DIR` 下的 React 构建产物
- 在进程内跑单执行器，处理解析/报告/AI 分析任务

入口：`server/main.go`；模块名 `qingliu`，Go 1.26。

## 2. 启动配置

生产通过 `/etc/qingliu/qingliu.env` 注入（不要提交真实值）：

| 变量 | 说明 |
| --- | --- |
| `MYSQL_DSN` | MySQL 8 DSN，专用库/用户 |
| `PUBLIC_ORIGIN` | 唯一外部源，HTTPS，不带末尾斜杠 |
| `VAULT_KEY` | 64 位 hex，AES-256-GCM 文件加密；不可随意更换 |
| `DATA_DIR` | 加密原件与报告目录 |
| `STATIC_DIR` | `frontend/dist` |
| `PDF_FONT` | 中文 PDF 字体 |
| `LISTEN_ADDR` | 默认 `127.0.0.1:8787` |
| `GOMEMLIMIT` / `GOMAXPROCS` | 资源约束 |
| `WORKBENCH_BASE_URL` | 工作台后台地址 |
| `WORKBENCH_SERVICE_CLIENT` / `WORKBENCH_SERVICE_SECRET` | service login 凭证 |

启动时执行 `schema.sql` 的 `CREATE TABLE IF NOT EXISTS`，不会清空旧表。结构变更必须另做版本化迁移。

## 3. 关键文件

| 文件 | 作用 |
| --- | --- |
| `main.go` | 配置、路由、会话/Cookie/CSRF、登录、计费代理、静态服务 |
| `store.go` | MySQL 连接池、查询/事务辅助、加密文件读写、审计 |
| `schema.sql` | 12+ 张 `ql_*` 表 |
| `workbench.go` | 工作台 service login、token 加密保存、计费转发 |
| `worker.go` | 单执行器、任务恢复、解析/报告任务 |
| `parser.go` | CSV/XLSX/PDF 文本提取、OCR、版式规则 |
| `domain.go` | 金额、方向、期间、月均、统计等业务规则 |
| `report.go` | PDF/Excel/HTML 报告与快照 |
| `ai_analysis.go` | 文档 AI 分析，走工作台默认模型 |
| `domain_test.go` / `parity_test.go` / `integration_test.go` | 单元/对照/集成测试 |

## 4. 会话与安全

- 登录成功生成随机会话 token，存 `ql_sessions`，Cookie `HttpOnly; Secure; SameSite=Lax`（HTTPS 时）
- 每个会话有 CSRF token；前端从 `/api/me` 取 `csrf`，写请求带 `X-CSRF-Token`
- 业务响应 `Cache-Control: no-store`
- 登录失败按 IP+账号计数，5 次锁 15 分钟；Nginx 还有 `limit_req`
- 密码 bcrypt；本地密码仅迁移期兜底
- 原始资料/报告用 AES-256-GCM 认证加密后落盘；报告带 SHA256

## 5. 工作台桥接

`loadWBConfig()` 读取 `WORKBENCH_BASE_URL`、`WORKBENCH_SERVICE_CLIENT`、`WORKBENCH_SERVICE_SECRET`。

- `POST /api/v1/service/auth/login`，body `{email, password, service_code:"qingliu"}`，带 `X-Service-Client` / `X-Service-Secret`
- 返回 access/refresh token 后，清流把 token 加密存 `ql_workbench_accounts`
- 后续计费请求用 `Authorization: Bearer <access_token>`
- token 过期用 refresh token 刷新
- 浏览器永远看不到 service secret 或工作台 token

## 6. 执行器

- `ql_jobs` 记录 queued/running/done/failed；浏览器关闭不取消
- 单执行器用 MySQL 命名锁防多实例并发；进程退出后由 systemd 重启
- 解析/报告任务幂等；失败写 message，可重试
- 客户修改与后台处理使用同一客户锁，处理期间阻止修改
- `/tmp` 逐页 OCR，避免整份扫描件同时渲染

## 7. 测试

```bash
cd server
go test ./...
go vet ./...
```

集成测试需要独立 MySQL 测试库：

```bash
MYSQL_DSN='qingliu_test:...@tcp(127.0.0.1:3306)/qingliu_test?charset=utf8mb4' PDF_FONT=../fonts/NotoSansSC.ttf go test -v ./...
```

没有测试库时集成用例会跳过；不要把它当成全部通过。

## 8. 不要做

- 不要引入第二个数据库/Redis/消息队列来解决单机任务
- 不要在浏览器保存工作台 service secret 或模型 Key
- 不要改 `VAULT_KEY` 或绕过 `Store.seal/unseal` 写文件
- 不要直接改线上表结构而不回写迁移
