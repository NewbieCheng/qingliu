# 03 · 数据模型

数据库：MySQL 8，库名 `qingliu`，表前缀 `ql_`。字段定义以 `server/schema.sql` 为准。

## 表清单

| 表 | 作用 |
| --- | --- |
| `ql_users` | 本地用户（admin/sales/reviewer），bcrypt 密码，active 停用 |
| `ql_sessions` | 会话 token、CSRF、过期时间 |
| `ql_workbench_accounts` | 工作台账号映射、加密 access/refresh token |
| `ql_customers` | 客户，`payload` JSON 保存表单/状态 |
| `ql_grants` | 客户 → 用户授权（多对多） |
| `ql_documents` | 资料元数据、SHA、加密文件引用 |
| `ql_transactions` | 逐笔交易，`fingerprint` 用于重复隔离 |
| `ql_reviews` | 人工核对记录（label/operator/reason） |
| `ql_jobs` | 后台任务（kind/status/payload/message） |
| `ql_submissions` | 客户当前提交快照（revision + payload） |
| `ql_reports` | 正式报告快照（job_id 唯一） |
| `ql_events` | 操作审计 |
| `ql_login_failures` | 登录失败计数 |
| `ql_ai_analyses` | AI 文档分析任务/结果 |

## 关键语义

- `ql_customers.revision`：资料/归属/核对变更时递增；报告绑定 revision，旧报告不因新资料变化而失效。
- `ql_documents.sha`：同客户内唯一，用于重复上传隔离。
- `ql_transactions.fingerprint`：同一客户内查重；跨客户不合并。
- `ql_jobs`：解析/报告任务由 Go 执行器消费；状态流转 queued → running → done/failed。
- `ql_reports.job_id` 唯一：一个报告任务只产出一份正式快照。
- `ql_workbench_accounts` 的 token 列是 VARBINARY，由 `VAULT_KEY` 加密后写入。
- `ql_events` 只追加，不用于业务状态。

## 文件存储

数据库保存元数据和加密文件路径/引用；真实原件与报告在 `DATA_DIR`：

- 文件格式 QLGO1（`VAULT_KEY` 派生的 AES-256-GCM 认证加密）
- 文件路径由 Store 管理，不要绕过 Store 直接读写
- 数据库、`DATA_DIR`、`VAULT_KEY` 必须来自同一恢复点

## 迁移

当前没有独立 migration 工具；`schema.sql` 仅启动建表。新增字段/索引时：

1. 在测试库执行 `ALTER TABLE` 并回归
2. 更新 `schema.sql` 供新环境
3. 在发布文档记录 SQL 与回滚方式
4. 生产先备份，再执行，再验证

不要用“删库重建”解决生产结构问题。
