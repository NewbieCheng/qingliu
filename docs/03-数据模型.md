# 03 · 数据模型

数据库：MySQL 8，库名 `qingliu`，表前缀 `ql_`。字段定义以 `server/schema.sql` 为准。

## 表清单

| 表 | 作用 |
| --- | --- |
| `ql_users` | 本地**影子账号**：给会话/任务/事件当外键。**不是**账号真相，没有独立密码真相 |
| `ql_sessions` | 会话 token、CSRF、过期时间、`space_kind`/`space_id`（本会话所在空间） |
| `ql_workbench_accounts` | 工作台账号映射、加密 access/refresh token、`permissions` 权限码快照 |
| `ql_customers` | 客户，`payload` JSON 保存表单/状态，`workspace_tenant_id` + `owner_user_id` 定归属 |
| `ql_grants` | 客户 → 授权绑定：`user_id` 指向本地影子行，`workbench_user_id` 是**真正的授权主体** |
| `ql_documents` | 资料元数据、SHA、加密文件引用 |
| `ql_transactions` | 逐笔交易，`fingerprint` 用于重复隔离 |
| `ql_reviews` | 人工核对记录（label/operator/reason） |
| `ql_jobs` | 后台任务（kind/status/payload/message/progress/stage/`space_*`） |
| `ql_upload_batches` | 上传批次幂等（断网重试不重复建任务） |
| `ql_submissions` | 客户当前提交快照（revision + payload） |
| `ql_reports` | 正式报告快照（`job_id` 唯一） |
| `ql_events` | 操作审计（`space_kind`/`space_id` 定会话坐标） |
| `ql_login_failures` | 登录失败计数 |
| `ql_ai_analyses` | AI 文档分析任务/结果（progress/stage） |

## 关键语义

- `ql_customers.revision`：资料/归属/核对变更时递增；报告绑定 revision，旧报告不因新资料变化而失效。
- `ql_customers.workspace_tenant_id` / `owner_user_id`：资料归属。团队管理员看全企业；团队非管理员看本企业且被 `ql_grants.workbench_user_id` 授权的；个人空间看自己创建的或被授权的（`scopeWhere`）。
- `ql_grants.workbench_user_id`：授权主体是**工作台身份**，不是本地角色。团队空间的客户可见性按这一列判；`user_id` 只为外键完整性保留。
- `ql_documents.sha`：同客户内唯一，用于重复上传隔离。
- `ql_transactions.fingerprint`：同一客户内查重；跨客户不合并。
- `ql_jobs`：状态流转 queued → running → done/failed；超过 30 分钟未终态会被 `sweepStaleJobs` 标失败。
- `ql_jobs.progress`/`stage`：只用于界面展示，不参与计费/权限/签发判断。
- `ql_reports.job_id` 唯一：一个报告任务只产出一份正式快照。
- `ql_workbench_accounts` 的 token 列是 VARBINARY，由 `VAULT_KEY` 加密后写入。
- `ql_sessions.space_kind/space_id`：**本会话所在空间**（`personal` / `team` / `platform` + id）。切换只改这一行，不影响同一个人在其他设备上的登录。
- `ql_workbench_accounts.permissions`：工作台权限码快照（JSON 数组）。有快照时权限判定**只看快照**；为空时退回 `ql_users.role` 兜底。
- `ql_events` 只追加，不用于业务状态；只有 `auditActionCatalog` 里的动作会落库。

## 文件存储

数据库保存元数据和加密文件引用；真实原件与报告在 `DATA_DIR`：

- 文件格式 QLGO1（`VAULT_KEY` 派生的 AES-256-GCM 认证加密）
- 文件路径由 Store 管理，不要绕过 Store 直接读写
- 数据库、`DATA_DIR`、`VAULT_KEY` 必须来自同一恢复点

## 迁移

没有独立 migration 工具；`schema.sql` 只做启动建表，**不会给已有表补列**。新增字段/索引时：

1. 在测试库执行 `ALTER TABLE` 并回归
2. 更新 `schema.sql` 供新环境
3. 加 `server/migrations/NNN-*.sql`（必须可重复执行）
4. 发布时按编号顺序用 root 手动执行，先备份

现有脚本（`server/migrations/`，全部幂等）：

| 脚本 | 内容 |
| --- | --- |
| `001-audit-indexes.sql` | `ql_events` 分页索引 |
| `002-job-progress.sql` | `ql_jobs.progress/stage/upload_batch`、`ql_upload_batches` |
| `003-tenant-isolation.sql` | 资料归属隔离（后被 005 改名到 `workspace_tenant_id`） |
| `004-session-space.sql` | 会话空间坐标 + 工作台权限快照（后被 005 改写为 `space_kind/space_id`） |
| `005-drop-local-space-columns.sql` | 加 `ql_sessions/ql_jobs.space_kind/space_id`，删清流自有的空间列 |
| `006-event-space.sql` | `ql_events.space_kind/space_id` + 回填；操作记录按空间隔离 |
| `007-grant-workbench-binding.sql` | `ql_grants.workbench_user_id` + 回填 + `idx_grants_wb`；客户授权绑工作台身份 |

**005、006、007 必须执行**（漏 005/006 会 1054；漏 007 授权写入缺列、业务员看不到被授权客户）。详见 `server/migrations/README.md`。

不要用"删库重建"解决生产结构问题。

## 索引

`ql_events` 分页与筛选依赖：

```sql
INDEX(user_id, seq)   INDEX(action, seq)   INDEX(created, seq)   INDEX(space_kind, space_id, seq)
```

新库由 `schema.sql` 直接创建；已有库执行 `server/migrations/001-audit-indexes.sql` 与 `006-event-space.sql`、`007-grant-workbench-binding.sql`。
