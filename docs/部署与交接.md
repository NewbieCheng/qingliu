# 部署与交接（给程序员）

## 交付范围

Go + React + MySQL 的独立网页源码及预编译Linux amd64/arm64产物。没有Python运行依赖，没有Node常驻进程，没有PostgreSQL、Redis或消息中间件。React由Go同源提供；后台单执行器内置于Go服务。

部署的MySQL只需复用已有实例，建一个专用库。不要为此额外启动第二套数据库。MySQL连接池上限8，应用容器默认2CPU/1GB，Go软内存目标512MiB，初始设置适配8核4GB共享主机，仍须结合其他服务实际占用验收。

## 需要填写的配置

1. `MYSQL_DSN`：团队已有MySQL的连接地址、专用库及专用用户。MySQL8.0+/8.4、utf8mb4、InnoDB；不要使用root作为生产应用账号。用户需在专用库内有建表/索引与增删查改权限。应用启动只执行CREATE TABLE IF NOT EXISTS，不会清空旧表；将来的结构升级须版本化执行。
2. `PUBLIC_ORIGIN`：完整且唯一的外部源，例如 `https://qingliu.example.com`，不带末尾斜杠、路径。HTTPS时Cookie会启用Secure，不能再用普通HTTP测试登录；正式域名与此值必须一致。
3. `VAULT_KEY`：`openssl rand -hex 32`生成的64位十六进制密钥；每套部署独立。密钥更换不是自动轮换，直接替换会导致旧原件/报告无法解密。与备份分开受控保存。

`.env.example`只有占位符，复制后编辑`.env`并chmod600。API中转目前未用，没有要填写的AI Key。

专用库示例（在已有MySQL管理员会话执行；密码自行替换；允许的主机范围按现有Docker网络收紧）：

```sql
CREATE DATABASE qingliu CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'qingliu'@'YOUR_APP_NETWORK' IDENTIFIED BY 'YOUR_RANDOM_DB_PASSWORD';
GRANT SELECT,INSERT,UPDATE,DELETE,CREATE,INDEX,REFERENCES ON qingliu.* TO 'qingliu'@'YOUR_APP_NETWORK';
```

Go驱动DSN中的数据库密码包含特殊分隔符时应按驱动格式配置；建议专用随机长密码使用字母数字生成器，避免误解析。远程MySQL按团队策略配置TLS（驱动DSN支持`tls=true`）。

## Docker部署（默认）

在交付包根目录执行README中的start/init-admin命令。默认Compose只启动web一个服务，命名卷`qingliu_data`保存加密原件和报告。`.env`在容器启动时注入，不打进镜像。

宿主机MySQL可用`host.docker.internal`；Linux Compose已配置host-gateway，但MySQL必须监听Docker网桥可达地址并授权应用来源，不能只监听127.0.0.1。若已有MySQL在Docker网络内，把web加入该已有网络，并在DSN用MySQL服务名；不要用容器内127.0.0.1。

`bash deploy/init-admin.sh`交互读取账号/密码，通过环境传入临时CLI容器；用户名/密码不作为命令参数。首次创建完成后自动禁止再次初始化。初始管理员由你们创建，无预置生产密码。

Nginx示例假设反向代理运行在宿主机，转发到127.0.0.1:8787；如反代也在容器内，需要加入共同网络，用web:8787，不是反代容器的127.0.0.1。复用已有证书和反向代理，不需要另外装一套。配置上传上限64MB、读写超时130秒，关闭业务代理缓存。任务本身在后台运行，页面不长时间占用上传请求等待解析。

构建镜像需要从Docker Hub/Debian获取基础镜像和系统工具。受限服务器可由CI构建并推到团队现有镜像仓库；无需在4GB服务器上编译Go/React。两个架构二进制都已包含，Docker按目标架构选择。

## 无Docker部署

Debian/Ubuntu安装`poppler-utils poppler-data mupdf-tools tesseract-ocr tesseract-ocr-chi-sim ca-certificates`，不需要Python/Node。将包放到`/opt/qingliu`，建立专用低权限系统账号，为`/var/lib/qingliu`赋予该账号0700权限。选择`bin/qingliu-amd64`或`bin/qingliu-arm64`。

通过受控的环境文件设置MYSQL_DSN、VAULT_KEY、PUBLIC_ORIGIN，另设置：

```text
DATA_DIR=/var/lib/qingliu
STATIC_DIR=/opt/qingliu/frontend/dist
PDF_FONT=/opt/qingliu/fonts/NotoSansSC.ttf
LISTEN_ADDR=127.0.0.1:8787
GOMEMLIMIT=512MiB
GOMAXPROCS=2
```

用该系统账号执行二进制的`init-admin`子命令，短期从环境传ADMIN_USERNAME、ADMIN_PASSWORD，之后清除两者。通过现有systemd模板管理服务，Restart=on-failure，MemoryMax=1G，WorkingDirectory=/opt/qingliu，启动参数为对应二进制；只给数据目录和隔离临时目录写权限。不要以root运行Web服务。

## 上线验收

- /health返回ok；实际HTTPS域名可以登录，Secure Cookie有效；HTTP跳转HTTPS。
- 用samples/synthetic.csv按“银行卡流水”上传，确认归属，核对疑点，确认期间，生成草稿并下载PDF/汇总Excel/逐笔底稿/网页。
- 新建两个业务员，验证不能互看客户；复核员仅在授权后可见；业务员不能签发正式报告；停用/改密撤销会话。
- 停止服务后重启，等待中的任务可继续；正式报告在资料变化后仍可下载原快照，旧复核不能直接用于新版本。
- 客户原件和报告在磁盘为QLGO1加密格式，浏览器业务响应no-store，assets为带哈希静态缓存。
- 用团队实际银行版式逐笔抽查，核对行数、收支方向、总额、重复隔离、资料范围与日期口径。新银行版式不自动视为已验收。
- 观察`docker stats`及现有MySQL/其他服务内存：至少覆盖一份长PDF、一次中文PDF输出及一份OCR任务。不要直接按8核开8个解析器。

## 备份、更新与回退

同时备份专用MySQL库、qingliu_data卷和对应VAULT_KEY；使用团队现有加密备份系统，密钥单独保存。MySQL业务字段没有额外应用层加密，备份文件不能公开传递。

一致性备份时先停止web（内置执行器会一起停止），再做专用库事务一致性导出与数据卷快照，最后启动；中断任务会在重启后恢复。SQL库与文件卷必须来自同一恢复点。不要用`docker compose down -v`，它会删除数据卷。

升级前备份并保存旧镜像标签；新代码执行`deploy/build.sh`产生二进制和静态文件后构建新镜像。回退镜像时保持数据卷和密钥不变；如果将来有不兼容数据库迁移，先按版本方案恢复专用库，不能盲目仅回退镜像。

旧项目的SQLite与Fernet原件格式不兼容新MySQL/AES-GCM。历史迁移需单独在受控环境进行，逐项验证持有人、权限、交易金额、复核记录与报告SHA；本包不包含旧客户数据库或自动迁移脚本。旧档案留在原电脑原项目，可继续使用原版查阅。
