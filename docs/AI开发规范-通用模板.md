# AI 开发规范 · 通用模板（交给 AI 的开工前必读）

> **使用方式（两种任选）**
> 1. **整段贴给 AI**：作为新项目开工前的第一条指令；
> 2. **落到仓库**：复制为项目根目录的 `AGENTS.md` 或 `docs/00-AI开发规范.md`，之后每次对话无需重贴。
>
> **规则属性**：本文全部为**硬约束**，不是建议。与业主当次口头要求冲突时，先指出冲突点，由业主决定，不得自行放宽。
> **填写方式**：所有 `{{大括号}}` 为占位符。派发前必须填满，未填的写「未指定」而不是猜。填充示例见附录 A。

## 零、AI 开工前必须走的流程（照做，不许跳步）

1. **读**：本规范 → 项目 `README.md` → 项目 `docs/` 索引中与你任务相关的文档。
2. **定位**：先查代码图 / 搜索定位符号与调用链；不熟悉的仓库先建索引；**不许凭猜改文件路径**。
3. **复述并等待确认**，输出以下 5 行后再动手：
   ```
   需求理解：…
   环境：{{生产 / 测试 / 本地}}（明确这次只改本地）
   拟改文件：…（逐个列出）
   是否触碰红线：…（对照第九节逐条说明）
   不做什么：…（本次明确排除的范围）
   ```
4. **最小改动**：只改点名的地方；不顺手重构、不补无关测试文件、不改无关文档、不动格式化。
5. **自检**：跑第八节「验证基线」；失败先修，修不了如实告知。
6. **交付说明**：改了哪些文件、为什么、怎么验证的、**哪些没验证**。不得声称已验证。

> 业主说「先看一眼/只讨论」时：只输出定位结果与分析，**不改任何文件**。

## 三、目录结构与依赖方向（强约束）

```text
{{项目根}}/
├── {{前端目录}}/
│   ├── src/
│   │   ├── {{入口，只挂载}}
│   │   ├── {{app/        应用总装、路由表、守卫、错误边界、查询缓存}}
│   │   ├── {{pages/      页面组合}}
│   │   ├── {{features/   业务域，每域一个目录}}
│   │   └── {{shared/     公共能力：请求、路由、布局、UI、工具、样式}}
│   ├── scripts/          {{架构边界检查、冒烟测试}}
│   └── {{dist/           交付产物，禁止手改}}
├── {{后端目录}}/
│   ├── {{入口文件：路由、中间件、启动、配置}}
│   ├── {{数据访问层}}
│   ├── {{业务规则}}
│   ├── {{schema}}
│   └── {{migrations/     版本化迁移 SQL}}
├── {{部署目录}}/
└── docs/
```

**依赖方向只能从上到下**：`{{app → pages → features → shared}}`

| 规则 | 违反后果 |
| --- | --- |
| `shared` 不得依赖 `features` / `pages` | 架构检查失败 |
| `pages` 不得直接发请求、不得直接引用请求底层 | 架构检查失败 |
| 同一 feature 内部用**相对路径** | 架构检查失败 |
| 跨 feature 只能引用对方 `index.js` | 架构检查失败 |
| 内部跳转只能用路由 API，禁止 `window.location.href =` | 架构检查失败（整页刷新） |
| 后端按职责**单文件分块**，不自行新建无意义的 package 层级 | 代码评审驳回 |

## 四、前端必守规则

1. **请求链路唯一**：`page → feature/api.js → 统一请求封装 → 后端`
   - CSRF、401 跳登录、超时、错误类型、网络错误文案**只**在统一请求层处理。
   - 新接口 = 在对应 feature 的 `api.js` 加一个函数，**不准写进组件**。
2. **查询缓存唯一入口**：`{{app/queries/index.js}}` 定义 key + TTL；缓存原语只在 `{{shared/api/cache.js}}`。
   - 列表**必须服务端分页**，不准前端拉全量再切。
   - 写操作成功后**先失效相关缓存再刷新**；退出登录 / 401 必须清空全部缓存。
   - 缓存只放内存，**禁止**写 `localStorage` / `sessionStorage`；资金、权限、签发结果**不得**依赖缓存判断。
3. **页面只做组合**：业务逻辑下沉到 feature；页面文件超过 `{{比如 200 行}}` 必须拆分。
4. **样式**：颜色、字体、间距优先用 `{{tokens.css}}`；不引入 CSS 框架、不写魔法值。
5. **文案与格式化**：金额、日期、角色名、状态文案只在 `{{format 工具 / constants}}` 定义一次。
6. **图标**：统一图标模块，不用字符拼图标。
7. **提示**：成功 / 失败统一走 Toast，不在表单内自绘绿/红条。
8. **新增页面的固定动作**：新建 `pages/<name>/` → 必要时 `features/<domain>/` → 注册路由 → 按需改导航 → 在 feature `index.js` 导出。
9. **响应式**：`{{390px}}` 宽度不得横向溢出（冒烟测试会检查）。
10. **禁止**：`any` 式隐式契约、在组件里直接拼 URL、在组件里做权限判断的唯一依据。

## 五、后端必守规则

1. **路由集中注册**在入口文件，格式统一（`METHOD /api/... + 路径变量`），**不准**散落在业务文件里零散注册。
2. **中间件统一处理，不要重复实现**：panic→JSON、安全响应头、并发槽位、请求体上限、会话识别、未登录 401、写请求 Origin + CSRF 校验。**新接口自动继承**。
3. **错误抛出**：用统一错误函数（`bad(code, "中文可读提示")`），不准裸 `500` 或框架默认错误页。
   - 面向用户的提示语**不得**暴露 SQL、路径、堆栈、内部服务名。
4. **权限**：资源级接口必须校验归属，**无权限返回 404 而不是 403**（防探测）；管理接口独立守卫；写资源走统一加锁入口。
5. **数据访问全部经统一数据层**（`query` / `one` / `exec` / `lock` / `event` / 文件读写），不准在 handler 里直接用 `db`。
   - 参数永远用占位符，**禁止字符串拼接 SQL**。
6. **JSON 契约**：请求体走统一解析（拒绝尾随内容、数字精确保留）；响应走统一序列化；**字段命名数据库 / 后端 / 前端保持一致**，改动必须三处同步并在交付说明里写明。
7. **审计**：关键写操作写审计事件表；审计查询走**独立分页接口**，不准在总览接口里附带全量数据。
8. **后台任务**：长任务投递到执行器并落任务表，不阻塞 HTTP；不准裸 goroutine 跑无记录任务；任务需写进度，重启可恢复。
9. **文件**：落盘必须走统一存储层（按需加密），数据库只存索引、元数据、加密路径。
10. **输出物（报告 / 导出）**：由服务端生成；正式版本是**快照**，后续数据变化不覆盖已签发版本。
11. **数据库变更**：
    - 启动建表脚本只解决「新库」；
    - 给已有表加字段 / 索引，必须在 `migrations/` 新建**按版本命名**的 SQL，并更新迁移说明的上线顺序；
    - **人工确认 + 先备份**后执行；禁止直接改线上表而不回写迁移文件。

- 无法验证（无测试环境、需要密钥等）必须在交付说明里**明确写「未验证」**，不得声称已验证。
- 交付产物目录 `{{dist/ 等}}`：改源码后必须重新构建，**禁止只改产物**；本机构建产物默认不入库。
- 禁止的检查方式：全库重构式格式化、为了过检查而改断言、跳过脚本直接 commit。

## 九、红线（任何情况下不得触碰）

1. ❌ 在业务系统里另建账号 / 支付 / 订单库，或绕开既有外部系统直接改计费。
2. ❌ 未经批准引入 Redis、消息队列、第二个常驻服务、改变部署形态。
3. ❌ 恢复单文件大组件；把业务逻辑塞回页面。
4. ❌ 页面直接发请求 / 直接引用请求底层。
5. ❌ 缓存写入本地存储，或用缓存做资金、权限、签发结果的最终判断。
6. ❌ 字符串拼接 SQL；在 handler 里绕过数据层直接写文件。
7. ❌ 把真实密钥、服务器密码、真实客户数据写进代码或提交。
8. ❌ **自动** `git commit` / `push` / 部署 / 发版——除非业主明确说「提交 / 推送 / 上线 / 发布」。
9. ❌ 提交 `node_modules`、`.env.local`、`.secrets/`、构建产物。
10. ❌ 未经确认改接口字段名、状态码、会话 / CSRF 机制（会同时打破前后端契约）。

## 十、AI 协作纪律

- **先问后动**：信息不足或要动多个模块时，用一句话问清，不猜着大改。
- **只改点名的地方**：不顺手加功能、不顺手重构、不改无关文件的格式。
- **不编造**：不确定的 API、库用法、报错原因，先查文档 / 搜索，不凭记忆写。（项目内结构问题优先查代码图，不靠 grep 猜。）
- **不假装验证过**：没跑的命令不说跑过，没看的文件不说看过。
- **冲突时停下**：发现需求与红线、与现有架构冲突，停下来指出来，给两个方案，等业主选。

## 十一、新增一个功能的标准动作（模板，照着做）

```text
1. 后端  {{入口}}            加路由 + 权限守卫
2. 后端  {{数据层}}          加查询 / 写入（占位符、分页）
3. 后端  {{审计}}            写操作记录事件
4. 后端  {{业务层}}          业务规则（如涉及金额 / 周期 / 状态机）
5. 前端  features/<域>/api.js            加接口函数
6. 前端  app/queries/index.js            如需缓存，定义 key + TTL 与失效函数
7. 前端  features/<域>/components/Xxx.jsx 纯展示 / 交互
8. 前端  pages/<name>/XxxPage.jsx         只做组合
9. 前端  features/<域>/index.js           导出
10. 自检 {{检查命令}} → 必要时 {{冒烟命令}}
```

## 十二、一句话总纲

> **保持既定栈与既定部署形态；前后端只通过 API JSON 契约通信；所有请求走统一通道，所有数据走统一数据层，所有表变更走版本化迁移；不新增框架、不新增服务、不碰红线；先复述再动手，改完必须自检，没验证就明说。**
