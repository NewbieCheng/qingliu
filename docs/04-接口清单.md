# 04 · 接口清单

所有接口同源，默认 JSON。写请求需带会话 Cookie 和 `X-CSRF-Token`（从 `/api/me` 获取）。业务响应 `no-store`。

## 公共

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/health` | 真实 ping 数据库，ok 才算健康 |
| POST | `/api/login` | 工作台 service login 优先，本地密码兜底；密码登录**需要图形验证码** |
| GET | `/api/me` | 当前用户、角色、工作台绑定、`permissions` 权限码快照、csrf |
| POST | `/api/logout` | 退出并删会话 |
| POST | `/api/password` | 修改本地密码，撤销其他会话 |
| GET | `/api/spaces` | 这个人能进的**空间**（个人 + 各企业），`current` 标记当前 |
| POST | `/api/switch-space` | body `{tenant_id}`，切换本会话所在空间（0=个人） |

### 空间（2026-11）

`/api/spaces` 与 `/api/switch-space` 都**先问工作台**（`GET /api/v1/me/spaces`、`POST /api/v1/me/switch-space`）再落库：
清流不自己判断「谁能进哪个企业」，只保存用户的选择。切换只改 `ql_sessions.tenant_id` 一行，
不影响同一个人在其他设备上的登录。细节见 [16-空间与权限投影](16-空间与权限投影.md)。

`/api/me` 的 `user` 现在多两个字段：

| 字段 | 含义 |
| --- | --- |
| `permissions` | 工作台权限码快照（`qingliu.admin`、`qingliu.case.write`、`qingliu.report.sign` 等）。前端按它显示/隐藏按钮 |
| `scope` | `team` / `personal`，由**会话空间**决定（不再只是 `ql_users.tenant_id`） |

## 管理端操作记录查询

### `GET /api/admin/audit`

仅管理员。服务端分页，默认每页 20 条，最大 100 条。

参数：`page`、`page_size`、`action`、`user_id`、`q`、`from`、`to`。
返回：`events`、`count`、`page`、`page_size`、`actions`。

`action` 只接受服务端白名单；事件带 `action_label` 和 `category`，前端不再硬编码动作中文名。
`GET /api/admin` 只返回成员，不再携带操作记录。详见 `12-查询与缓存.md`。

## 新增：登录、注册与 AI 队列（2026-11-08）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/login` | 增加 `login_mode`：`1` 个人、`2` 团队；账号字段兼容 `username`/`email`/`phone` |
| POST | `/api/register` | 邀请码 + 邮箱验证码注册个人账号，成功后直接建立会话 |
| GET | `/api/auth/captcha` | 代理工作台图形验证码 |
| POST | `/api/auth/verification-codes` | 代理工作台邮箱验证码（`purpose=register`） |
| POST | `/api/clients/{cid}/upload` | 返回 `{ok,jobs,batch}`；同 `batch` 重试幂等回放 |
| GET | `/api/clients/{cid}/jobs` | 任务返回 `progress`、`stage` 用于进度条 |

AI 分析不再是裸 goroutine：提交后写 `ql_jobs(kind=ai_analysis)`，由单 worker 执行并通过 `ql_ai_analyses.progress/stage` 展示阶段进度；失败原因保留工作台 `reason_code` 与 `trace_id`。
