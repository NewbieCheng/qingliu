# 04 · 接口清单

所有接口同源，默认 JSON。写请求需带会话 Cookie 和 `X-CSRF-Token`（从 `/api/me` 取）。业务响应 `no-store`。

## 公共与会话

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/health` | 真实 ping 数据库，ok 才算健康 |
| POST | `/api/login` | 工作台 service login 优先，本地密码兜底；**需要图形验证码** |
| POST | `/api/register` | 邀请码 + 邮箱验证码注册个人账号，成功后直接建会话 |
| POST | `/api/auth/reset-password` | 代理工作台重置密码 |
| GET | `/api/auth/captcha` | 代理工作台图形验证码 |
| POST | `/api/auth/verification-codes` | 代理工作台邮箱验证码（`purpose=register`） |
| GET | `/api/me` | 当前用户、角色、权限码快照、空间、csrf |
| POST | `/api/logout` | 退出并删会话 |
| POST | `/api/password` | 修改本地密码，撤销其他会话 |
| GET | `/api/spaces` | 能进的空间（个人 + 各企业），`current` 标记当前 |
| POST | `/api/switch-space` | body `{kind, id}`，切换本会话所在空间 |
| POST | `/api/spaces/enable` | body `{kind, id}`，在工作台开通个人空间 |

`/api/me` 的 `user` 关键字段：

| 字段 | 含义 |
| --- | --- |
| `permissions` | 工作台权限码快照，前端据此显示/隐藏按钮 |
| `space` / `kind` / `scope` | 当前空间，`{kind, id}`；`kind ∈ personal\|team\|platform` |
| `space_name` / `role_label` | 来自工作台 `/me/spaces`，清流不另起名字 |
| `workbench_linked` | 是否已绑定工作台账号 |

**这里没有 `tenant_id`**：一个人可在多个空间间切换，「所属团队」不是账号属性。

空间类接口都**先问工作台**（`/api/v1/me/spaces`、`/me/switch-space`、`/me/spaces/enable`）再落库；清流不自己判断「谁能进哪个企业」。切换只改 `ql_sessions.space_kind/space_id`，不影响其他设备。`/api/switch-space` 仍接受旧的 `{tenant_id}` 形状，只为兼容旧前端产物。

## 计费代理（转发工作台）

`GET /api/billing/skus`、`POST /api/billing/orders`、`GET /api/billing/orders[/{order_no}]`、`GET /api/billing/balance`、`GET /api/billing/ledgers`。

清流不直接写支付表；订单在 `WORKBENCH_BASE_URL` 指向的工作台库。详见 [11](11-工作台后台.md)。

## 客户与底稿

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/clients` | 当前空间可见客户（服务端分页，`q` + `page`） |
| POST | `/api/clients` | 新建客户 |
| GET | `/api/clients/{cid}` | 底稿数据（可按来源/日期过滤） |
| POST | `/api/clients/{cid}/upload` | 上传（multipart），返回 `{ok, jobs, batch}`；同 `batch` 重试幂等回放 |
| POST | `/api/clients/{cid}/ownership` · `/coverage` · `/rules` · `/review` | 确认归属 / 纳入范围 / 规则阈值 / 逐笔核对 |
| GET | `/api/clients/{cid}/transaction/{tid}` | 交易详情 |
| GET | `/api/clients/{cid}/original/{did}/{page}` | PDF 原页（带 ETag / `X-Document-SHA`） |
| POST | `/api/clients/{cid}/submit` · `/report` | 提交复核 / 生成报告 |
| GET | `/api/clients/{cid}/reports/{rid}/{file}` | 下载报告 |
| GET | `/api/clients/{cid}/jobs` | 任务状态（含 `progress`、`stage`） |
| POST | `/api/clients/{cid}/jobs/{jid}/cancel` · `/retry/{jid}` | 终止 / 重试任务 |
| GET/POST | `/api/clients/{cid}/ai-analysis` | AI 分析记录 / 发起 |

写接口统一走 `q.edit()`：先校验空间访问，再抢客户锁，客户有在跑任务时返回 409。

## 管理

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/admin` | 团队成员（以工作台企业成员为准，同步本地影子账号） |
| GET | `/api/admin/audit` | 操作记录分页查询，见 [12](12-查询缓存与操作记录.md) |
| POST | `/api/admin/users` | 新增成员（实际调工作台开户） |
| POST | `/api/admin/users/{uid}/toggle` | 停用/启用（以工作台账号状态为准） |
| POST | `/api/clients/{cid}/grant` | 授权/取消授权（绑 `workbench_user_id`） |

`GET /api/admin` 只返回成员，不再附带操作记录。

## 服务间接口

由 `X-Service-Client` / `X-Service-Secret`（= `WORKBENCH_SERVICE_*`）鉴权，不走浏览器 CSRF：`GET /api/service/audit`（工作台运维中心读清流操作记录）、`POST /api/service/audit/purge`（触发留存清理）。

## 上游工作台接口（清流调用）

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/api/v1/service/auth/login` | service login（**必须带图形验证码**） |
| POST | `/api/v1/auth/refresh` | 刷新 token |
| GET | `/api/v1/me/spaces` · POST `/me/switch-space` · POST `/me/spaces/enable` | 空间 |
| GET/POST/PUT | `/api/v1/tenant/members[/open]`、`/members/{id}/status` | 企业成员与新开户、启停 |
| GET | `/api/v1/payment/skus?service_code=qingliu` | 套餐 |
| POST/GET | `/api/v1/payment/orders[/{order_no}]` | 下单（可带 `owner_type/owner_id` 买给企业）/ 订单 |
| GET | `/api/v1/payment/balance` / `ledgers`、`/api/v1/account/balance` | 余额 / 账本（企业空间下读企业池） |
| POST | `/api/v1/service/billing/charge` | 解析成功后扣积分（服务凭证） |
| GET | `/api/v1/service/billing/parse-pricing` | 解析三档单价（服务凭证） |

具体字段以工作台 `api/openapi/openapi.yaml` 为准；本文档只记录清流侧调用面。
